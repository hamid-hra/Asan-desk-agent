# Asan-desk-agent

ایجنت پایش آسان‌دسک. یک کانتینر کوچک (Python) که روی سرور اجرا می‌شود و به پنل آسان‌دسک گزارش می‌دهد:

| گزارش | توضیح |
|---|---|
| منابع سرور | CPU، RAM، دیسک، پهنای باند کارت‌های فیزیکی، تعداد اتصال‌های TCP، تأخیر شبکه تا پنل |
| وضعیت `hbbs` و `hbbr` | بالا/پایین بودن، مدت کار، CPU و RAM هر کدام (از روی پروسهٔ آن‌ها) |
| دستگاه‌های ثبت‌شده در hbbs | شناسه، آخرین IP ثبت‌شده و تاریخ اولین ثبت‌نام، از دیتابیس خود hbbs. این‌ها در فهرست «کلاینت‌ها»ی پنل با برچسب «قدیمی» می‌آیند؛ کلاینت‌های قدیمی به API پنل گزارش نمی‌دهند و فقط از همین راه دیده می‌شوند |
| اثرانگشت کلید سرور | sha256 فایل `id_ed25519.pub` برای سنجش یکسان‌بودن کلید سرورهای HA |

## نصب

۱. در پنل: **HA ← افزودن سرور** و ساخت توکن. هر سرور توکن مخصوص خودش را دارد؛ یک توکن را روی دو سرور نگذارید.

۲. روی سرور (دستور آماده در همان دیالوگ هم هست):

```bash
git clone https://github.com/hamid-hra/Asan-desk-agent.git && \
docker build -t asandesk-agent Asan-desk-agent && \
docker run -d --name asandesk-agent --restart unless-stopped --pid host \
  -e AGENT_URL=https://panel.example.com/api/agent/ingest \
  -e AGENT_TOKEN=<TOKEN> \
  -e AGENT_DISK_PATH=/hostfs -e AGENT_SYS=/hostsys \
  -e AGENT_HBBS_DIR=/hbbs \
  -v /:/hostfs:ro -v /sys:/hostsys:ro \
  -v /path/to/hbbs-data:/hbbs:ro \
  asandesk-agent
```

`/path/to/hbbs-data` همان پوشه‌ای است که hbbs فایل‌های `id_ed25519`، `id_ed25519.pub` و `db_v2.sqlite3` را در آن نگه می‌دارد (روی میزبان؛ با `docker inspect hbbs --format '{{json .Mounts}}'` پیدایش کنید).

> توکن را در جایی که عمومی است (README، issue، اسکریپت در ریپو) نگذارید.

روی سروری که hbbs ندارد (مثلاً خود سرور پنل) `AGENT_HBBS_DIR` و mount آخر را نگذارید؛ فقط منابع سرور گزارش می‌شود.

### به‌روزرسانی و حذف

```bash
cd Asan-desk-agent && git pull && docker build -t asandesk-agent . && docker rm -f asandesk-agent   # سپس دستور docker run بالا
docker rm -f asandesk-agent                                                                           # حذف
```

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `AGENT_URL` | `http://localhost:8000/api/agent/ingest` | آدرس دریافت گزارش پنل |
| `AGENT_TOKEN` / `AGENT_TOKEN_FILE` | الزامی (یکی از دو) | توکن سرور؛ در پنل ساخته می‌شود |
| `AGENT_INTERVAL` | `15` | فاصلهٔ گزارش (ثانیه) |
| `AGENT_DISK_PATH` | `/hostfs` | مسیری که دیسک میزبان از آن اندازه‌گیری می‌شود |
| `AGENT_SYS` | `/sys` | برای خواندن سرعت کارت شبکه (mount میزبان: `/hostsys`) |
| `AGENT_PORTS` | خالی (همهٔ اتصال‌ها) | فقط اتصال‌های این پورت‌ها شمرده شود، مثلاً `21116,21117` |
| `AGENT_NET_CAPACITY_MBPS` | تشخیص خودکار یا ۱۰۰۰ | ظرفیت لینک شبکه |
| `AGENT_IP` | خالی | IP نمایش‌داده‌شده برای این سرور |
| `AGENT_PING_TARGET` | خود پنل | مقصد اندازه‌گیری تأخیر (`host:port`) |
| `AGENT_HBBS_DIR` | خالی | پوشهٔ دادهٔ hbbs (فقط‌خواندنی). با آن وضعیت hbbs/hbbr و دستگاه‌های ثبت‌شده هم گزارش می‌شود |
| `AGENT_KEY_FILE` | `$AGENT_HBBS_DIR/id_ed25519.pub` | مسیر کلید عمومی سرور شناسه |
| `AGENT_SERVICES` | `hbbs,hbbr` (فقط وقتی `AGENT_HBBS_DIR` هست) | نام پروسه‌هایی که وضعیتشان گزارش می‌شود |
| `AGENT_PEERS_INTERVAL` | `600` | هر چند ثانیه دیتابیس hbbs سنجیده شود (فقط اگر عوض شده باشد فرستاده می‌شود؛ هر ۶ ساعت هم یک‌بار کامل) |
| `AGENT_PEERS_URL` | `AGENT_URL` با `/ingest`→`/peers` | آدرس دریافت فهرست دستگاه‌ها |
| `LOG_LEVEL` | `INFO` | |

## چه چیزی می‌خواند و به چه چیزی دست نمی‌زند

ایجنت فقط می‌خواند و هیچ تغییری در سرور نمی‌دهد:

- **بدون `docker.sock`.** وضعیت hbbs/hbbr از `/proc` و با `--pid host` خوانده می‌شود، فقط برای پروسه‌هایی که نامشان دقیقاً در `AGENT_SERVICES` است. کانتینرهای دیگر دیده نمی‌شوند و هیچ دستوری اجرا نمی‌شود.
- **پوشهٔ hbbs فقط‌خواندنی است** (`:ro`). برای خواندن دیتابیس، `db_v2.sqlite3` و `-wal` به یک پوشهٔ موقت داخل خود ایجنت کپی می‌شوند و روی کپی کار می‌شود؛ فایل‌های hbbs هرگز قفل یا نوشته نمی‌شوند.
- **بدون تغییر شبکه:** نه `--network host`، نه `NET_RAW`، نه پورت تازه. hbbs و hbbr ری‌استارت نمی‌شوند و تنظیمشان عوض نمی‌شود.
- ایجنت فرمانی از پنل نمی‌پذیرد؛ فقط گزارش می‌فرستد.
- `uuid` دستگاه‌ها از سرور بیرون نمی‌رود؛ فقط `sha256` آن (همان که پنل از heartbeat کلاینت‌های جدید هم ذخیره می‌کند) فرستاده می‌شود تا وقتی دستگاه قدیمی نسخهٔ جدید را نصب کرد، همان ردیف به کلاینت عادی تبدیل شود.
- IP هر دستگاه همان است که hbbs هنگام ثبت کلید ذخیره کرده (آخرین IP ثبت‌شده، نه لحظه‌ای).

**وضعیت آنلاین/آفلاین دستگاه‌های قدیمی** مشخص نیست: hbbs آن را فقط در حافظهٔ خودش نگه می‌دارد و بدون تغییر در سرور راه خواندنش نیست؛ پنل برای آن‌ها «نامشخص» نشان می‌دهد.
