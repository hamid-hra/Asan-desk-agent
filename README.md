# Asan-desk-agent

ایجنت پایش آسان‌دسک. یک کانتینر کوچک (Python) که روی سرور اجرا می‌شود و به پنل آسان‌دسک گزارش می‌دهد:

| گزارش | توضیح |
|---|---|
| منابع سرور | CPU، RAM، دیسک، پهنای باند کارت‌های فیزیکی، تعداد اتصال‌های TCP، تأخیر شبکه تا پنل |
| وضعیت `hbbs` و `hbbr` | بالا/پایین بودن، مدت کار، CPU و RAM هر کدام (از روی پروسهٔ آن‌ها) |
| دستگاه‌های ثبت‌شده در hbbs | شناسه، آخرین IP ثبت‌شده و تاریخ اولین ثبت‌نام، از دیتابیس خود hbbs. این‌ها در فهرست «کلاینت‌ها»ی پنل با برچسب «قدیمی» می‌آیند؛ کلاینت‌های قدیمی به API پنل گزارش نمی‌دهند و فقط از همین راه دیده می‌شوند |
| اثرانگشت کلید سرور | sha256 فایل `id_ed25519.pub` برای سنجش یکسان‌بودن کلید سرورهای HA |

## نصب

۱. در پنل: **HA ← افزودن سرور** و ساخت توکن. هر سرور توکن مخصوص خودش را دارد؛ یک توکن را روی دو سرور نگذارید.

۲. روی سرور (دستور آماده در همان دیالوگ هم هست؛ با `docker compose`، تا ایجنت از داخل پنل هم به‌روز شود):

```bash
git clone https://github.com/hamid-hra/Asan-desk-agent.git && cd Asan-desk-agent && \
printf 'AGENT_URL=%s\nAGENT_TOKEN=%s\nHBBS_DATA=%s\n' 'https://panel.example.com/api/agent/ingest' '<TOKEN>' '/path/to/hbbs-data' > .env && \
docker compose up -d --build
```

`/path/to/hbbs-data` همان پوشه‌ای است که hbbs فایل‌های `id_ed25519`، `id_ed25519.pub` و `db_v2.sqlite3` را در آن نگه می‌دارد (روی میزبان؛ با `docker inspect hbbs --format '{{json .Mounts}}'` پیدایش کنید).

> اگر قبلاً ایجنت را با `docker run` نصب کرده‌اید، اول `docker rm -f asandesk-agent` بزنید تا نام کانتینر آزاد شود.
>
> توکن را در جایی که عمومی است (README، issue، اسکریپت در ریپو) نگذارید؛ فایل `.env` در git نمی‌رود.

روی سروری که hbbs ندارد (مثلاً خود سرور پنل) خط `HBBS_DATA` را از `.env` پاک کنید؛ فقط منابع سرور گزارش می‌شود.

### به‌روزرسانی

- **از داخل پنل** (فقط ایجنتِ همان سروری که پنل رویش است): تنظیمات ← به‌روزرسانی پنل ← «ایجنت روی این سرور». پنل خودش در پوشهٔ ایجنت `git pull` و `docker compose up -d --build` می‌زند. ایجنت روی سرورهای دیگر را باید روی خود آن سرور به‌روز کرد.
- **دستی:**

```bash
cd Asan-desk-agent && git pull && docker compose up -d --build
```

### حذف

```bash
cd Asan-desk-agent && docker compose down
```

## آنلاین بودن دستگاه‌های قدیمی (اختیاری)

hbbs وضعیت آنلاین را فقط در حافظهٔ خودش دارد و بیرون نمی‌دهد. ولی هر دستگاه روشن هر ~۱۲ ثانیه یک بستهٔ UDP ساده با شناسهٔ خودش به پورت 21116 می‌فرستد. اگر بخواهید، ایجنت می‌تواند همین بسته‌ها را از روی کارت شبکه بخواند (فقط شناسه را نگه می‌دارد) و پنل «آنلاین/آفلاین» دستگاه‌های قدیمی را نشان بدهد:

یک خط به `.env` اضافه کنید و دوباره بالا بیاورید (با `COMPOSE_FILE` در `.env`، به‌روزرسانی از داخل پنل هم همین حالت را نگه می‌دارد):

```bash
echo 'COMPOSE_FILE=docker-compose.yml:docker-compose.sniff.yml' >> .env && docker compose up -d --build
```

این فقط به **کانتینر ایجنت** دو دسترسی می‌دهد (`network_mode: host` و `NET_RAW`)؛ hbbs، hbbr و کانتینرهای دیگر هیچ تغییری نمی‌کنند. برگشت: آن خط را از `.env` پاک کنید و دوباره `docker compose up -d --build` بزنید.

حدود این روش:
- فقط دستگاهی دیده می‌شود که با UDP ثبت‌نام می‌کند. اگر UDP برایش بسته است، با TCP رمزنگاری‌شده ثبت‌نام می‌کند و این راه آن را نمی‌بیند (شمار کل اتصال‌های TCP همچنان در منابع سرور هست).
- **سیستم‌عامل، نسخه و اینکه الان به کجا وصل است را نمی‌شود فهمید.** این‌ها در هیچ بسته‌ای که به hbbs می‌رسد نیست و P2P اصلاً از سرور رد نمی‌شود. فقط کلاینت جدید (که به API پنل گزارش می‌دهد) این اطلاعات را می‌فرستد.

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `AGENT_URL` | `http://localhost:8000/api/agent/ingest` | آدرس دریافت گزارش پنل |
| `AGENT_TOKEN` / `AGENT_TOKEN_FILE` | الزامی (یکی از دو) | توکن سرور؛ در پنل ساخته می‌شود |
| `AGENT_INTERVAL` | `15` | فاصلهٔ گزارش (ثانیه) |
| `AGENT_DISK_PATH` | `/hostfs` | مسیری که دیسک میزبان از آن اندازه‌گیری می‌شود |
| `AGENT_SYS` | `/sys` | برای خواندن سرعت کارت شبکه (mount میزبان: `/hostsys`) |
| `AGENT_PORTS` | خالی (همهٔ اتصال‌ها) | فقط اتصال‌های این پورت‌ها شمرده شود، مثلاً `21116,21117` |
| `AGENT_NET_CAPACITY_MBPS` | تشخیص خودکار یا ۱۰۰۰ | ظرفیت لینک شبکه |
| `AGENT_IP` | خالی | IP نمایش‌داده‌شده برای این سرور |
| `AGENT_PING_TARGET` | خود پنل | مقصد اندازه‌گیری تأخیر (`host:port`) |
| `AGENT_HBBS_DIR` | خالی | پوشهٔ دادهٔ hbbs (فقط‌خواندنی). با آن وضعیت hbbs/hbbr و دستگاه‌های ثبت‌شده هم گزارش می‌شود |
| `AGENT_KEY_FILE` | `$AGENT_HBBS_DIR/id_ed25519.pub` | مسیر کلید عمومی سرور شناسه |
| `AGENT_SERVICES` | `hbbs,hbbr` (فقط وقتی `AGENT_HBBS_DIR` هست) | نام پروسه‌هایی که وضعیتشان گزارش می‌شود |
| `AGENT_PEERS_INTERVAL` | `600` | هر چند ثانیه دیتابیس hbbs سنجیده شود (فقط اگر عوض شده باشد فرستاده می‌شود؛ هر ۶ ساعت هم یک‌بار کامل) |
| `AGENT_PEERS_URL` | `AGENT_URL` با `/ingest`→`/peers` | آدرس دریافت فهرست دستگاه‌ها |
| `AGENT_SNIFF` | خاموش | `1` = شنود ثبت‌نام‌های UDP برای آنلاین بودن دستگاه‌های قدیمی (بخش بالا؛ فقط با `docker-compose.sniff.yml`) |
| `AGENT_SNIFF_PORT` | `21116` | پورت UDP ثبت‌نام hbbs |
| `AGENT_ONLINE_WINDOW` | `45` | دستگاهی که در این چند ثانیه ثبت‌نام کرده آنلاین است |
| `AGENT_ONLINE_URL` | `AGENT_URL` با `/ingest`→`/online` | آدرس دریافت فهرست آنلاین‌ها |
| `LOG_LEVEL` | `INFO` | |

## چه چیزی می‌خواند و به چه چیزی دست نمی‌زند

ایجنت فقط می‌خواند و هیچ تغییری در سرور نمی‌دهد:

- **بدون `docker.sock`.** وضعیت hbbs/hbbr از `/proc` و با `--pid host` خوانده می‌شود، فقط برای پروسه‌هایی که نامشان دقیقاً در `AGENT_SERVICES` است. کانتینرهای دیگر دیده نمی‌شوند و هیچ دستوری اجرا نمی‌شود.
- **پوشهٔ hbbs فقط‌خواندنی است** (`:ro`). برای خواندن دیتابیس، `db_v2.sqlite3` و `-wal` به یک پوشهٔ موقت داخل خود ایجنت کپی می‌شوند و روی کپی کار می‌شود؛ فایل‌های hbbs هرگز قفل یا نوشته نمی‌شوند.
- **بدون تغییر شبکه** (حالت عادی): نه host network، نه `NET_RAW`، نه پورت تازه. hbbs و hbbr ری‌استارت نمی‌شوند و تنظیمشان عوض نمی‌شود. فقط اگر حالت شنود اختیاری را روشن کنید، خودِ کانتینر ایجنت این دو دسترسی را می‌گیرد.
- ایجنت فرمانی از پنل نمی‌پذیرد؛ فقط گزارش می‌فرستد.
- `uuid` دستگاه‌ها از سرور بیرون نمی‌رود؛ فقط `sha256` آن (همان که پنل از heartbeat کلاینت‌های جدید هم ذخیره می‌کند) فرستاده می‌شود تا وقتی دستگاه قدیمی نسخهٔ جدید را نصب کرد، همان ردیف به کلاینت عادی تبدیل شود.
- IP هر دستگاه همان است که hbbs هنگام ثبت کلید ذخیره کرده (آخرین IP ثبت‌شده، نه لحظه‌ای).

**وضعیت آنلاین/آفلاین دستگاه‌های قدیمی** بدون حالت شنود مشخص نیست و پنل «نامشخص» نشان می‌دهد.
